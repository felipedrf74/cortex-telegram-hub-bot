## 1. Product one-liner + target user
- One-liner (verbatim): "Nexus Hub is a personal operating system delivered through an iOS app and web surfaces, backed by a tenant-scoped runtime. It combines deterministic daily operations with bounded AI reasoning across five product skills: Secretary, Training, Content, Cooking, and Finance." (`WS/docs/01-product/PRODUCT_TRUTH.md:17-20`). App Store subtitle: "Your personal operating system" (`WS/docs/01-product/brand/APP_STORE_COPY.md`, frontmatter-status draft).
- Target user: the "principal" running their own operation — solo founders, athlete-creators, freelancers; "Not for teams. Not for enterprises."; "BUILT FOR THE PERSON RUNNING IT ALL" (`VOICE.md` §2, §4; `APP_STORE_COPY.md:41,147-149`). Initial market: Brazilian creators; website defaults to pt-BR (`VOICE.md`). Target user is not defined in `PRODUCT_TRUTH.md` itself (gap flagged by the desktop audit).
- Metaphor hierarchy [CLOSED]: "personal operating system" = category, "assistive brain" = experience, "chief of staff" = internal only — never mixed in one sentence (`VOICE.md` Appendix B Q1). Anti-positioning: "Not a chat app with AI tacked on… It's a system. The five skills coordinate." (`APP_STORE_COPY.md`). Tone: a "calm senior operator" that assumes competence — reference brands Linear × Oura × Raycast, explicitly not Duolingo/ChatGPT-flavored (`VOICE.md`; `WEB_COPY.md`).

## 2. Skills / surfaces + IA rules
- Exactly **five** product skills, all `state: available`: Secretary, Training, Content, Cooking, Finance (`PRODUCT_TRUTH.md:37-48`, `WS/docs/01-product/capability-map.json`). **Decision Center is not a skill** — platform capability `platform.decisions`, an aggregate for reviewable proposals/outcomes (`capability-map.json:15`, `WS/docs/02-architecture/PLATFORM.md`).
- Scopes (`PRODUCT_TRUTH.md:39-48`): Secretary = tasks/calendar/planning/reminders/coordination/reviewable decisions · Training = evidence-bound plans, readiness, adaptation, exercise media, schedule coordination · Content = research, ideas, canonical workspaces, generation, review, publishing · Cooking = recipes, pantry/preferences, meal planning, allergy safety, schedule-aware execution · Finance = expenses, invoices, vendors, durable financial state, jurisdiction-aware workflows. Subscription billing/entitlements are platform-owned, never Finance (`PLATFORM.md`).
- Tabs: Home, Chat, Tasks, Skills + a fifth tab. Shipped code = **Settings** (`IOS/Nexus Hub/Views/MainTabView.swift:119-147`; `tab-more` survives only as a stable accessibility/test id); `SCREENS.md:17` still says "More". `SCREENS.md:29-30` delegates exact navigation authority to iOS code, so Settings is current truth and "More" is doc drift (see §8).
- Skills hub contains exactly the four non-Secretary skills: "The Skills surface contains Training, Content, Cooking, and Finance" (`WS/docs/01-product/SCREENS.md:17-23`; four cards shipped in `IOS/Nexus Hub/Views/Skills/SkillsHubView.swift:19`). No doc states a literal "4 cards" count contract.
- **Secretary never gets a Skills card** — "expressed through Home, Tasks, Calendar and Plan, Decision Center, Inbox, and Chat actions rather than a duplicate skill card" (`SCREENS.md:17-23`).
- Every network-backed screen must distinguish loading / refresh / empty / partial / stale / unavailable / blocked / failed; cached or fixture state never presented as current truth (`SCREENS.md:25-27`).
- Other surfaces: Web Portal (operators) and a bounded Python Content Engine — "not an alternate public API or authority plane" (`WS/docs/02-architecture/SYSTEM_CONTEXT.md`).

## 3. Architecture (iOS ↔ Cortex, deterministic vs AI, token-zero)
- Topology: iOS app + Web Portal → Backend Runtime (repo `cortex-telegram-hub-bot`; user-facing name "Nexus Hub Engine" — "Cortex" appears in no canonical doc, only repo/path names) → bounded Python Content Engine, external providers, SQLite/caches/queues/object storage (`SYSTEM_CONTEXT.md`; `VOICE.md` §5).
- Base URL: `productionBaseURL = "https://api.nexushub.me"` (`IOS/Nexus Hub/Core/NexusConfig.swift:4`); staging `api-staging.nexushub.me`; supported iOS boundary is `/api/v1` (`WS/docs/03-contracts/APP_FACING_API.md:17`). No host is published inside the contract by design; DEBUG-only local overrides are gated (`NexusConfig.swift:49`).
- Contract: `CTX/docs/contracts/openapi-v1.yaml` — OpenAPI 3.1, "Nexus Hub iOS API — /api/v1 app-JWT surface", 336 paths / 386 operations derived from `src/api/router.ts` (no invented routes; governance `CTX/docs/engineering/backend-api-contract-standard.md` §11). `/api/v1/internal/*`, `/api/v1/admin/*`, portal, and the Apple server webhook are never part of the iOS contract.
- Auth/envelope: app-JWT bearer via `auth/register|refresh`; single-user tenancy `req.userId === req.tenantId` (violations = tenant-isolation bugs); envelope `{ok, data, cached, timestamp}` / `{ok:false, error:{code,message}}`; WebSocket reserved for chat + explicitly real-time events.
- **Token-zero is law:** every operation is tagged `x-nexus-kind: deterministic` (371 ops — never triggers a model completion) or `model-backed` (15 ops) (`openapi-v1.yaml:39-47`). Operational reads/writes (dashboard, tasks, calendar, training, notifications, settings, provider state) stay deterministic REST, cost zero LLM tokens, and remain available regardless of AI quota (ADR-0003 `WS/docs/05-decisions/adr/0003-token-zero-rest-direct-routes-source-of-truth.md`; `CTX/docs/TOKEN-QUOTA-CONTRACT.md:15-17`). No-model-on-operational-read tests are permanent release gates.
- Model-backed ops pass entitlement + dollar-budget gates (`src/services/entitlement.ts#getEffectiveEntitlement()`): stable errors `403 AI_PLAN_REQUIRED`, `429 AI_DAILY/MONTHLY_LIMIT_REACHED`, `429 SERVICE_DEGRADED`, `Retry-After` on stable 429s (`TOKEN-QUOTA-CONTRACT.md`; `openapi-v1.yaml:47`).
- AI flow: Intent → Scope → structured Proposal → deterministic policy/authorization → deterministic execution → authoritative read-back. "AI output never grants authority by itself"; model output cannot bypass authorization, entitlement, consent, confirmation, idempotency, provider ownership, or read-back checks (`WS/docs/02-architecture/AI_FLOW.md`; `PRODUCT_TRUTH.md:28-29`). Distinguish two scopes that the earlier one-liner collapsed: (a) the **conversational AI pipeline** (Intent → Scope → Proposal → policy → execution → read-back) is entered only via **chat and attachments** (`RUNTIME_FLOW.md`; `AI_FLOW.md`); (b) the OpenAPI surface separately tags **~15** operations `x-nexus-kind: model-backed` (count from `openapi-v1.yaml` — includes chat/attachments plus other bounded model routes such as content script/discover, training coach, finance parse-receipt, etc.), all still under entitlement/budget gates and never granting authority by themselves. Do not read (a) as shrinking (b) to two routes.
- Providers: OpenAI, Anthropic, Gemini, local models (`DATA_AND_INTEGRATIONS.md`). Free-tier AI is local-model-only (never cloud), staged rollout off→shadow→canary→active with auto-rollback + kill switches (`CTX/docs/engineering/local-primary-inference-standard.md`). Never hardcode a provider — route via `getActiveProvider(taskType)` / `completeOneShotWithFallback(...)` (contract-standard §10).
- Read path: event outbox + summary read models + delta sync (`/api/v1/sync/changes`) for first paint; read models are rebuildable projections, never authority (ADR-0001). Integrations: Microsoft Graph, Google Calendar, Todoist, Notion, HealthKit, Garmin, APNs, App Store Server API, Stripe, Sentry (`DATA_AND_INTEGRATIONS.md`).

## 6. Safety / never-do rules
- AI output never authorizes anything; deterministic policy gates every mutation; no fake chat commands for dashboard/tasks/calendar/skill workspaces/notifications/settings/Decision Center (`PRODUCT_TRUTH.md`; `AI_FLOW.md`; `RUNTIME_FLOW.md`).
- User/tenant/provider/entitlement/consent scope on every request, cache, prompt, job, notification, stored record; never hardcode a user, tenant, email, task title, simulator response, provider, or one-off backend shape into production Swift (`PRODUCT_TRUTH.md`; `IOS/AGENTS.md:29`).
- Honest degraded states, always: never fabricate current/connected/synchronized/successful state; cached/fixture data never presented as production truth (`PRODUCT_TRUTH.md`; `SCREENS.md`).
- Git/ops: never clean, reset, discard, amend, force-push, commit, push, archive, delete, deploy, release, or expire user work without explicit ask; never `--no-verify`; production mutation, remote-branch deletion, and TestFlight expiry require explicit owner authorization (`IOS/AGENTS.md:32-52`; `CTX/AGENTS.md:16`).
- Secrets/privacy: never expose secrets, private logs, OAuth tokens, raw provider responses, personal data, or finance/calendar content; no PII in iOS logs; Keychain items `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, non-synchronizable — iCloud-Keychain leak is a release blocker (`CTX/AGENTS.md`; `IOS/docs/engineering/ios-architecture-and-swiftui-performance-standard.md` §5, §9).
- Economics: every provider call through the atomic budget wrapper (`api_usage` is quota truth); unknown models fail preflight closed; GETs never mutate, call providers, or trigger completions; unchanged inputs must produce zero provider calls; independent kill switches for subscriptions, packs, Apple fulfillment, local inference, cloud fallback, storefront; AI learning stays provisional, redacted, tenant-safe, and may never auto-mutate prompts or initiate provider training (`backend-api-contract-standard.md` §6; `CTX/.agents/skills/product-sentinel/SKILL.md`).
- Release truth: "Git is not production truth" — never infer production state from git, branches, projections, fixtures, or caches; never reconstruct/copy/infer around a blocked release read (`WS/docs/07-operations/RELEASE_TRUTH.md`; `WS/AGENTS.md` Policy-Version 2026-08-09.release-authority.1). `PAID_AI_COST_CONTROLS_ENFORCEMENT_ENABLED` flips require staged persona matrix + explicit owner authorization (`CURRENT_RELEASE_STATE.md`).
- Docs: no per-session handoffs, dated audit reports, or competing release summaries; never hand-edit `docs/90-generated/`; Notion/Git mirrors must not override local truth; keep deployment target iOS 18 — an accidental iOS 26 bump is a release blocker (`WS/AGENTS.md`; `WS/docs/00-index.md`; `IOS/AGENTS.md`).

## 7. Verification / release gates
- Release truth = VPS evidence only: `/var/lib/nexus-release/state/release-state.json` + identity-bound immutable receipt (schema v3), read via `ssh "$DEPLOY_SERVER" sudo -n /usr/local/sbin/nexus-release-state-view`; malformed/receiptless state is unprovable and blocks release claims; checked-in `release-state.json` / `CURRENT_RELEASE_STATE.md` are non-authoritative projections (`RELEASE_TRUTH.md`; `CTX/docs/release/release-evidence-contract.md`). Delivery states — working-tree → CI artifact → staging → production, and `main` → TestFlight → App Store — are separate evidence states that may never be collapsed into one claim (`WS/docs/02-architecture/DELIVERY_LIFECYCLE.md`).
- Backend CD (`CTX/docs/release/continuous-deployment.md`): green CI on protected `main` deploys unattended — Ed25519-signed manifest; VPS poller runs staging → production with backup → migrate → switch ordering, 60-second observation, immutable receipt or restore of the predecessor; 120-second rollback objective; DB integrity failure hard-stops without rollback. PM2 remains the owner-gated fallback until 14 stable container days. (The older `CURRENT_RELEASE_STATE.md` projection — last verified 2026-07-10 — describes `release:verify:full` gates, signed evidence-reuse rules, and `auto-when-staged` default-off; prefer the CD doc on current `main`.)
- Backend local gates: `scripts/changed-area-classifier.sh --json` → `scripts/risk-gate.sh` (fail-closed, no silent full-suite fallback); `npm run verify` (typecheck + science-policy + risk-gate); `npm run docs:audit`; migration-hook lint; coverage + mutation thresholds in `config/test-policy.json`; `verifiable-reward-check` before ending non-trivial work (`CTX/AGENTS.md:40`).
