# Release Process Bottleneck Analysis

Date: 2026-05-01

## Primary Causes Of Slow Releases

| Bottleneck | Cause | Release impact | Recommended fix |
| --- | --- | --- | --- |
| Report sprawl | Hundreds of historical docs across domain folders; prompts require broad rereads. | Agents spend large time re-reading superseded reports and reconciling drift. | Keep one current release index per release; mark old reports historical. |
| Manual SHA/test-count copying | Release docs manually cite commits and counts. | Small docs commits invalidate the docs, causing another QA pass. | Generate identity with `scripts/release-identity.sh`; add stale-doc checker later. |
| Full verify after low-risk docs changes | `npm run verify` is repeatedly run after docs-only edits. | Adds about 8-10 minutes per docs correction. | Docs-only risk class should run doc checks and maybe `git diff --check`, not full backend verify. |
| iOS simulator repetition | Full/focused tests rerun with name-only destinations or after unrelated backend changes. | Simulator boot churn, clone windows, flaky state, and slow feedback. | Explicit UDID, single simulator, only iOS tests when iOS/contracts changed. |
| Local service setup repeated | Each smoke starts/stops local backend/cache/fixtures independently. | Setup time and orphan-process flakes accumulate. | Add shared local smoke harness and cleanup script; reuse one fixture backend per pass. |
| Staging/provider smoke run late | Calendar/provider risks are discovered after merge-like work is complete. | Late failures force rework and repeat release docs. | Run provider smoke immediately after calendar/agenda changes reach candidate state. |
| CI is not risk-based | Backend CI runs the same suite regardless of changed area; iOS CI does not run tests. | Slow where unnecessary and weak where needed. | Add changed-file classifier and matrix jobs. |
| Agent prompts duplicate gates | Prompts repeatedly ask for branch setup, all docs, all smokes, full tests, staging, TestFlight. | Each pass recreates the release process from scratch. | Replace large prompts with a release checklist generated by the risk classifier. |
| Production vs merge readiness blurred | Reports often mix merge readiness, staging readiness, and production readiness. | Safe merge candidates get blocked by production-only gates. | Adopt four distinct gates: merge, staging RC, production, postdeploy. |

## Slow But Necessary Gates

The following are slow but must stay for relevant changes:

- Tenant isolation and authorization tests for auth, memory, retrieval, content, Cooking, Chat, Finance, Training, portal/admin paths.
- Prompt-injection and unauthorized-context tests when prompt construction, retrieval, memory, or tool authorization changes.
- Calendar/agenda lifecycle and provider smoke when Secretary, Training, calendar mapping, provider sync, reminders, or cancellation code changes.
- iOS interaction validation when SwiftUI view, navigation, cache, decoder, or action code changes.
- Model-routing and fallback safety checks when provider registry, routing, tool filtering, env overrides, or operator overrides change.
- Staging smoke for app-facing or portal-facing behavior before production.

## Biggest Time Savings

1. Stop running full backend verify after docs-only fixes.
2. Stop running full iOS suite when only backend/docs changed.
3. Run provider calendar smoke only when calendar/provider code or data mapping changed.
4. Replace broad report rereads with a generated current-release index.
5. Parallelize backend typecheck, focused tests, migration check, and Python compile in CI.
6. Add a single simulator hygiene wrapper and require UDID destinations.
7. Make domain smoke scripts write structured artifacts so later QA can verify evidence without rerunning.
